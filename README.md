# SDI Open Water Study Notes

A quiet, ocean-themed Astro website for personal Chinese and English scuba study notes.

Website: **https://admijw.github.io/SDI-Open-Water-Scuba-Diver-Questions/**

The chapter Markdown files are the source of truth. Edit them in Obsidian as usual; they are read directly at build time. Correct answers and discussions remain visible. The EN / 中文 switch changes the interface, while note text remains as written.

In Self-hosted LiveSync **Setup → Enable extra and advanced features**, temporarily enable advanced features if needed. Open **Selector** and add this as a new pattern under **Normal Files → Non-Synchronising files**, then click **Apply**:

```text

```

Add the **same pattern** under **Hidden Files → Ignore patterns**, and click **Apply**. Preserve every existing pattern. You can restore the previous advanced-features toggle afterward; the exclusions remain effective. If the vault-relative directory differs on a device, adjust the prefix to its actual path using forward slashes.

These settings were applied through LiveSync’s interface on the development PC before application files were created. Existing AWS exclusions were preserved. Hidden-file sync remains disabled, and the previous advanced-features preference was restored.

## Develop and preview

Use **Node.js 24** and npm. From the repository root:

```powershell
cd site
npm ci
npm run dev
```

Open the local URL printed by Astro, including `/SDI-Open-Water-Scuba-Diver-Questions/`. For working full-text search, build and preview the static output:

```powershell
npm run test
npm run check
npm run build
npm run verify
npm run preview
```

The search bundle is generated by Pagefind after the Astro build; it is not generated by the development server. Both Chinese and English searches use the same static index. Press `/` to open search, and Escape to close it. Browser language determines the initial interface language, and manual choices are stored locally.

The homepage illustration includes a detailed scuba diver with a BCD, cylinder, mask, regulator, hoses, wrist computer, and fins. Staggered bubbles rise from the regulator, with a gentle fin stroke, buoyancy drift, and moving underwater light. All animation respects reduced-motion preferences, which leave a still underwater scene.

All application files, installed packages, assets, `.astro`, and `dist` stay under `site/`. Git ignores generated files; LiveSync excludes the complete application directory.

## Add and edit notes

- Add a root-level `.md` file to publish another page. No frontmatter or registration is required. Nested folders are not published.
- `README.md`, `AGENTS.md`, `CONTRIBUTING.md`, `CHANGELOG.md`, and `LICENSE.md` are excluded, ignoring filename case.
- Page URLs use `/notes/<filename-slug>/`, such as `/notes/chapter-14/`. Renaming a note changes its URL; no redirect is created. Duplicate URL slugs stop the build.
- Chapters sort by number; other notes follow alphabetically. Chapter numbering is retained, including the current start at Chapter 2.
- Root Markdown is never rewritten by the application. Question headings are rendered one level below the page title, and outlines reuse their generated anchors.
- Every build recalculates question counts, page navigation, and the search index. Deleting a note removes its page on the next successful deployment.

The existing Chapter 5 equations contain source formatting artifacts, including the third expression beginning `V2=14V_2`. They are preserved for the author to review. KaTeX renders math with nonfatal handling of unsupported source characters; the migration does not correct diving theory or source mistakes.

## Publish

Commit and push changes to **`master`**. `.github/workflows/deploy.yml` tests the content discovery, checks Astro/TypeScript, builds all pages, generates Pagefind search, verifies local links and anchors, and deploys the artifact to GitHub Pages. Pull requests run the same checks without deploying. A manual run is available in the repository’s Actions tab.

In **Settings → Pages**, the source must be **GitHub Actions**. Deployment uses the workflow’s `GITHUB_TOKEN`; no personal token, CouchDB credentials, or VPS service is needed. Failed builds leave the last successful deployment available. A newer deployment supersedes an older run. To roll back content or application changes, revert the relevant commit and push again.

After a push, verify the **Build and deploy study notes** workflow succeeds and visit the website, including a direct chapter URL and both Chinese and English searches.

LiveSync continues syncing your notes to CouchDB. It does not create Git commits or push to GitHub.
